# Ступень 2. Два review одного изменения

Результат: изменение specification.md, которое проверили другой аналитик и разработчик или архитектор. Нужны Git, редактор, доступ к PR/MR и два проверяющих. Node.js и OpenSpec не требуются.

Этот репозиторий пока подготовлен локально; удалённый адрес будет доступен после публикации. Здесь уже есть самостоятельная исходная [спецификация](specification.md). Результат ступени 1 можно приложить ссылкой; копировать файлы оттуда не требуется.

## Подготовьте изменение

Учебное решение: при ошибочном вводе очищать предыдущий успешный результат и показывать «—».

1. Создайте ветку из корня репозитория:

   ```bash
   git switch -c feature/error-result-review
   ```

2. Добавьте решение в требования и сценарий «120 000 ₽, 0%, 12 месяцев → 10 000 ₽; затем срок 1,5 месяца → ошибка и результат “—”». Закройте соответствующий открытый вопрос.
3. Прочитайте весь документ: четыре исходных сценария должны сохраниться. Проверьте diff:

   ```bash
   git diff --check
   git diff -- specification.md
   git add specification.md
   git commit -m "docs: specify clearing result on error"
   ```

4. После публикации репозитория выполните `git push -u origin feature/error-result-review` и откройте PR/MR своей ветки в main. Используйте [описание запроса](review/request.md). Создайте или откройте учебную Task DEMO под DEMO-1 с названием «Провести два review спецификации кредитного калькулятора» и добавьте ссылку на PR/MR.

## Проведите две проверки

Сначала другой аналитик читает требования и сценарии. После устранения его замечаний разработчик или архитектор проверяет реализуемость и полноту условий ошибки. Для обоих есть [единый список вопросов](review/request.md).

Каждое замечание обсуждайте в PR/MR: примите и исправьте либо объясните причину отклонения. Если не хватает решения по поведению, верните вопрос автору задачи. Комментарий ИИ не заменяет одобрение человека.

После нового коммита оба проверяющих должны подтвердить актуальную версию. Сливайте PR/MR, когда обсуждения разрешены и оба подтверждения относятся к текущему diff. В Jira сохраните ссылку на слитый запрос; переписывать спецификацию в описание задачи не нужно.

## ИИ-дополнение

До человеческих review выполните [ИИ-предпроверку](ai/request.md) в том же репозитории. Если она выявила ошибку, исправьте документ и снова покажите его людям. Заранее заполненных одобрений в эталоне нет.

## Проверка результата и следующий шаг

Результат доказан ссылкой на PR/MR, актуальным diff, решениями по замечаниям и двумя настоящими review. `git diff --check` подтверждает лишь оформление diff.

Дальше откройте самостоятельный эталон ступени 3: он содержит реализацию, тесты и OpenSpec. Переносить туда этот документ автоматически не нужно.
