# Необязательная ИИ-предпроверка R2

Сначала откройте MR R2 и получите review другого аналитика, затем разработчика или архитектора. После этого в том же репозитории и R2-ветке откройте панель Kilo в VS Code с утверждённой корпоративной моделью — проверенный маршрут курса; настройка описана в [корпоративных ресурсах](https://apolenkov.github.io/customdev-learning/corporate-resources.html#kilo-vscode), именованная альтернатива — OpenCode. Выберите режим без изменения файлов: в Kilo это **Ask**, в OpenCode — **Plan**. Затем скопируйте сообщение, заменив `your_login`:

```text
Прочитай AGENTS.md, README.md, specification.md, transfer.md и
review/request.md. Проведи только дополнительную предпроверку текущего R2.

Проверь ветку, чистоту Git и фактический diff
course/your_login/stage-1-error-result...HEAD по specification.md и
transfer.md. Личный результат R1 уже принят: при ошибке прежний результат
очищается до «—», сообщение указывает ошибочное поле, пять сценариев R1
сохранены. Новая дельта R2: «Сбросить» возвращает 3 000 000 ₽, 16% и
240 месяцев, очищает ошибки и результат до «—», не запускает расчёт;
повторный сброс не меняет состояние, не запускает расчёт и не показывает
ошибку. В итоговом договоре восемь
сценариев.

Верни конкретные замечания с местом, причиной и предлагаемой правкой.
Если замечаний нет, перечисли, что фактически проверено. Ничего не исправляй,
не создавай другую ветку или MR, не добавляй Node.js/OpenSpec или приложение,
не выполняй commit/push и не выдавай ИИ-проверку за человеческое одобрение.
```

Разберите замечания. Принятые правки внесите в текущую R2-ветку, проверьте, закоммитьте и отправьте в тот же MR. Если source изменился, оба человека должны повторно подтвердить актуальный diff; прежние review не переносятся автоматически.

Затем продолжите [ручную R3 в этой же папке](https://apolenkov.github.io/customdev-learning/guides/stage-3.html). Второй clone не нужен.
