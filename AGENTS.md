# Правила отдельного старта R2

- Этот репозиторий предназначен только для позднего старта. Ученик, уже завершивший R1, не переходит сюда: он продолжает в своей текущей папке и ветке.
- Поздний старт выполняет R1 и R2 в этом checkout: `stage-1-error-result` → `stage-2-reset`. Не клонируйте R1 рядом и не импортируйте готовое решение из другого эталона.
- `specification.md` в общей `main` — исходное состояние с открытым вопросом, а не готовое решение ученика. Сначала внесите R1 в личной ветке и зафиксируйте фактическое происхождение в `transfer.md`.
- Перед clone создайте fork через интерфейс GitHub Enterprise и клонируйте URL своего fork. В локальном checkout `origin` указывает на ваш fork; второй remote для обычного учебного маршрута не нужен.
- PR R2 сравнивает head `stage-2-reset` с личной base `stage-1-error-result`, не с общей `main`. После двух review его можно смёржить в личную base-ветку fork, но не в общую `main`; force push и обход защиты запрещены.
- R2 определяет три сценария сброса. Повторный сброс не меняет состояние, не запускает расчёт и не показывает ошибку.
- R2 обязательно включает commit, push, PR, review другого аналитика и затем review разработчика или архитектора. 2-ИИ выполняется только как необязательная предпроверка; принятые после неё правки получают повторные review обоих людей.
- На R1/R2 меняйте только Markdown-договор и учебные документы. Не добавляйте Node.js, OpenSpec, npm-инструменты или код приложения.
- Для R3 оставайтесь в этой папке, обновите правила под R3 и следуйте native OpenSpec-инструкции. Не клонируйте сервисный пример, не запускайте Apply и не отмечайте задачи реализации выполненными. 3-ИИ создаёт отдельный `add-payment-summary` в ветке `stage-3-ai-payment-summary` с PR в личную R3.
- Проверяйте полные SHA из Git и актуальный diff. При грязном дереве, неверном источнике, неизвестной Jira-задаче или нехватке прав остановитесь; не подменяйте факты и одобрения.
- Не сохраняйте секреты, токены, персональные данные и корпоративные документы в Git, сообщениях агенту или URL.

Сопровождение эталона владельцем в отдельной maintenance-ветке не является учебным прохождением и регулируется задачей сопровождения.
