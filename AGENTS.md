# Правила отдельного старта R2

- Этот репозиторий предназначен только для позднего старта. Ученик, уже завершивший R1, не переходит сюда: он продолжает в своей текущей папке и ветке.
- Полный курс: Введение → R1 → R2 → обязательная практика SDD и OpenSpec → R4; R3 факультативна. Поздний старт выполняет R1 и R2 в этом checkout: `course/<логин>/stage-1-error-result` → `course/<логин>/stage-2-reset`. Не клонируйте R1 рядом и не переносите готовое решение из другого эталона.
- До R1 ученик разбирает исходное обращение, заполняет общий шаблон и формирует один intent. Он развивается на R1–R3; отдельное намерение и новая папка для каждого шага не создаются.
- `specification.md` в общей `main` — исходное состояние с открытым вопросом, а не готовое решение ученика. Сначала внесите R1 в личной ветке и зафиксируйте фактическое происхождение в `transfer.md`.
- Перед clone создайте fork через интерфейс GitLab и клонируйте URL своего fork. В локальном checkout `origin` указывает на ваш fork; второй remote для обычного учебного маршрута не нужен.
- MR R2 сравнивает source `course/<логин>/stage-2-reset` с личным target `course/<логин>/stage-1-error-result`, не с общей `main`. Для текущего diff курса обязательны отметки руководителя проекта, аналитика и технического руководителя; при архитектурном изменении или споре нужна четвёртая отметка архитектора. После них MR можно смёржить в личную base-ветку fork, но не в общую `main`; force push и обход защиты запрещены.
- R2 определяет три сценария сброса. Повторный сброс не меняет состояние, не запускает расчёт и не показывает ошибку.
- R2 обязательно включает commit, push, MR и три отметки по текущему diff. Если используете необязательную помощь ИИ, принятые предложения сохраняются в той же ветке; для изменённого diff отметки обновляются. Отдельные AI-ветки и упражнения не нужны.
- На R1/R2 меняйте только Markdown-договор и учебные документы. Не добавляйте Node.js, OpenSpec, npm-инструменты или код приложения.
- Факультативную R3 можно выполнить в этой папке от принятой ветки `course/<логин>/stage-2-reset`; обновите правила под R3 и следуйте native OpenSpec-инструкции. Это рабочий способ ручного планирования без модели, но полный курс всё равно включает обязательные SDD и R4. Не клонируйте сервисный пример, не запускайте Apply и не отмечайте задачи реализации выполненными.
- Проверяйте актуальный diff и фактическое состояние Git; полный SHA фиксируйте только там, где он нужен для происхождения или передачи. При грязном дереве, неверном источнике, неизвестной Jira-задаче или нехватке прав остановитесь; не подменяйте факты и одобрения.
- Не сохраняйте секреты, токены, персональные данные и корпоративные документы в Git, сообщениях агенту или URL.

Сопровождение эталона владельцем в отдельной maintenance-ветке не является учебным прохождением и регулируется задачей сопровождения.
